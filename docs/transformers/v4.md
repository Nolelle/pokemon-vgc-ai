# Transformer v4 (`rust_v4_m256_l6_novmeta`)

> **Takeaway:** `v4` was our first attempt to double the Transformer's capacity (`256×6`, `ffn_mult=3`, **6.40M params**) and introduce `policy_version=3` (static move facts, Speed/TR rank cues, 90-group preview), trained **from scratch** for 4,000,013 games (~13 hours). It **severely underperformed** (losing **-105 Elo** to 3M-game `v3` and **-161 Elo** to `v3c`), and was never deployed live. A deep 10,832-game post-mortem proved the new `v3` features actually *helped* — the failure was caused by **5 concrete trainer bugs** plus cold-starting a 2× bigger brain, which we fixed before launching `v3d` and `v4b`.

## 2. What We Built & Changed from v3c

- **New `RUST_POLICY_VERSION = 3` architecture (kept for `v3d` & `v4b`):**
  - Scaled from `192×6` (`ffn_mult=2`, 3.32M params) to `256×6` (`ffn_mult=3`, **6.40M params**).
  - Added frozen **32-feature static move metadata** from `data/champions/moves.json` (type, category, base power, accuracy, priority, spread/Protect/contact/sound flags) so rare moves generalize immediately.
  - Added GPU-computed fog-safe **effective Speed + Trick Room move-order rank cues** over living active Pokémon.
  - Replaced the 360-way Team Preview head with a **90-group permutation-invariant Team Preview head** (4× faster and 4× less GPU RAM).
- **New rating-weighted team manifest (`v4_nov_meta_weighted_manifest.json`):** Preserved all 696 unique Reg M-C teams while up-weighting `>=1500` Elo teams from `22.0% -> 45.1%` of sampled games.
- **Trainer changes introduced in `v4`:** Undiscounted `--gamma 1.0`, decoupled `AdamW`, `--snapshots-per-wave 2`, EMA-capped PFSP win-rate tracking (`max_effective_games=200`).

## 5. First-Principles Post-Mortem: 5 Root Causes Found

Component ablations first **cleared the `policy_version=3` architecture**:
- `Preview(v4) + Turn(v3)` tied `v3` at **50.2%**, while `Preview(v3) + Turn(v4)` lost **34.0% (-115 Elo)**.
- Zeroing out `move_meta_proj` or `speed_proj` hurt `v4` by **-5 to -10 percentage points**, proving the new domain features genuinely helped!

The actual failure came from **5 root causes**:
1. **Early PPO trust-region breakdown:** Because `target_kl` was only checked *after* a full epoch, `approx_kl` exploded to **0.067–0.160** across games 232k–895k, permanently scrambling the policy's early representations.
2. **100× weight-decay drop + unscaled LR on wider layers:** Cutting `weight_decay` from `1e-2 -> 1e-4` while keeping `lr=1e-4` on a wider `256×6` (`ffn_mult=3`) network amplified per-step KL by ~6×.
3. **MPS memory leak + `--resume` seed replay bug:** `dev == "mps"` evaluated to `False` for `torch.device("mps", 0)`, skipping GPU cache cleanup and leaking MPS RAM until crashes forced 7 restarts — and each `--resume` reset `VecEnv` to fixed `seed=37401`, replaying the exact same 400k-game matchup prefix **7 times**.
4. **Noisy 200-game PFSP EMA window:** Made historical opponent selection jittery.
5. **Cold-starting a 2× bigger model from zero:** Starting a 6.40M-param brain from random weights threw away 11M–15M games of already-learned VGC fundamentals.

All 5 bugs were immediately fixed (and verified with unit tests) before launching **`v3d`** and **`v4b`**.
